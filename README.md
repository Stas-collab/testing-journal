# Серверний застосунок для обробки та зберігання результатів тестування студентів

Цей проект розроблено в рамках практичного завдання: **«Розробка серверного застосунку для обробки та зберігання результатів тестування студентів»**. Застосунок є повноцінним full-stack (SPA + API Server) продуктом, що використовує **Node.js/Express** для бекенду, **MongoDB** (через Mongoose) для збереження даних з можливістю підключення та адміністрування через **MongoDB Compass**, та **React (Vite + Tailwind CSS + motion)** для сучасного інтерактивного інтерфейсу.

---

## 📂 Структура проекту

Проект чітко розділений на клієнтську (фронтенд) та серверну (бекенд) частини в одному зручному репозиторії (monorepo):

```text
├── server.ts              # Головна точка входу бекенд-сервера Express
├── server/                # Модулі серверної частини (Бекенд)
│   ├── db.ts              # Контролер підключення до бази даних та CRUD-операції
│   └── models.ts          # Схеми та моделі Mongoose для MongoDB (Student, Test, Result)
├── src/                   # Клієнтська частина (Фронтенд на React)
│   ├── main.tsx           # Точка входу React-додатка
│   ├── App.tsx            # Головний компонент з маршрутизацією та бічним меню
│   ├── api.ts             # Адаптер для комунікації з бекенд API через HTTP-запити
│   ├── types.ts           # Спільні TypeScript-інтерфейси для клієнта
│   ├── components/        # Загальні UI-компоненти (Модальні вікна, ScoreRing тощо)
│   └── pages/             # Сторінки інтерфейсу:
│       ├── LoginPage.tsx          # Авторизація (Викладач або Студент)
│       ├── StudentsPage.tsx       # Панель управління студентами (для викладачів)
│       ├── TestsPage.tsx          # Конструктор тестів та запитань (для викладачів)
│       ├── ResultsPage.tsx        # Зведена аналітика та відомість оцінок (для викладачів)
│       ├── StudentTestsPage.tsx   # Інтерфейс проходження тестів (для студентів)
│       └── StudentResultsPage.tsx # Екзаменаційні листки та історія спроб (для студентів)
├── db.json                # Локальна база даних (автоматичний fallback, якщо MongoDB вимкнено)
├── package.json           # Залежності проекту, скрипти збірки та запуску
├── vite.config.ts         # Конфігурація збирача Vite
└── .env.example           # Приклад налаштування змінних оточення (URI бази даних)
```

## 🛠️ Використаний технологічний стек

### **Бекенд (Server-side)**:
*   **Node.js & Express** — швидкий серверний каркас для реалізації RESTful API.
*   **MongoDB & Mongoose** — документо-орієнтована СУБД для зберігання та гнучкого моделювання даних. Схеми включають реляційні зв'язки між студентами, тестами та спробами складання.
*   **Cors** — безпечний обмін ресурсами між клієнтом та сервером.

### **Фронтенд (Client-side)**:
*   **React 18 (TypeScript)** — інтерактивна бібліотека для побудови реактивного інтерфейсу користувача.
*   **Vite** — надшвидкий інструмент збірки фронтенду.
*   **Tailwind CSS** — утилітарний CSS-фреймворк для стилізації інтерфейсу за концепцією **Sleek Interface** (витончений, світлий, висококонтрастний дизайн).
*   **Lucide React** — набір сучасних векторних іконок.
*   **Motion (Framer Motion)** — плавні анімації переходів між сторінками та взаємодії з елементами.

## 💻 Як запустити проект локально (як справжній продукт)

Ви можете завантажити весь цей проект у вигляді ZIP-архіву прямо з меню **Settings -> Export ZIP** в інтерфейсі AI Studio та розпакувати його на своєму комп'ютері.

### Крок 1. Запуск бази даних (MongoDB Compass)
1.  Переконайтеся, що на вашому комп'ютері встановлено **MongoDB Community Server** та утиліту **MongoDB Compass**.
2.  Запустіть службу MongoDB локально (зазвичай вона запускається автоматично на порті `27017`).
3.  Відкрийте **MongoDB Compass** та підключіться до локального сервера за замовчуванням: `mongodb://localhost:27017`.
4.  Застосунок автоматично створить базу даних з назвою `studenttests` та відповідні колекції (`students`, `tests`, `results`) при першому запуску, а також виконає первинне наповнення (seed) демонстраційними даними.

### Крок 2. Встановлення залежностей
Відкрийте термінал у папці розпакованого проекту та виконайте команду:
```bash
npm install
```

### Крок 3. Налаштування змінних оточення (опціонально)
Створіть файл `.env` у корені проекту на основі `.env.example`:
```env
MONGODB_URI="mongodb://localhost:27017/studenttests"
```
*Примітка: Якщо сервер не зможе підключитися до MongoDB за вказаною адресою, він автоматично перейде у режим роботи з локальним файлом `db.json`, що гарантує безвідмовність системи за будь-яких умов.*

### Крок 4. Запуск у режимі розробки (Development)
Для запуску сервера та клієнта в один клік виконайте:
```bash
npm run dev
```
Сервер запуститься за адресою **`http://localhost:3000`**. Перейдіть за цим посиланням у браузері для тестування застосунку!

### Крок 5. Компіляція та Production-запуск
Для підготовки продукту до реального розгортання виконайте збірку:
```bash
npm run build
```
Ця команда оптимізує фронтенд у папку `dist/` та збирає серверний код у компактний файл `dist/server.cjs` за допомогою `esbuild`.

Після цього запустіть готовий продакшн-застосунок командою:
```bash
npm start
```

## 📊 Демонстраційні акаунти для захисту практики

При першому запуску база даних автоматично наповнюється тестовими даними для зручної демонстрації:

### 1. Режим Викладача (Teacher):
*   Виберіть роль **Викладач** на сторінці входу.
*   Оберіть будь-якого викладача зі списку (наприклад, **Олександр Коваль**).
*   **Функціонал**: Створення та редагування карток студентів, формування груп, розробка нових інтерактивних тестів, додавання запитань та варіантів відповідей (з позначенням правильного варіанту), детальний перегляд відомостей успішності та екзаменаційних листків студентів, видалення застарілих спроб.

### 2. Режим Студента (Student):
*   Виберіть роль **Студент** на сторінці входу.
*   Оберіть студента (наприклад, **Андрій Коваленко** або **Марія Шевченко**).
*   **Функціонал**: Перегляд доступних тестів, запуск проходження тесту у реальному часі (з анімованим індикатором прогресу), автоматичний підрахунок балів на сервері за захищеним алгоритмом, перегляд власної детальної історії результатів та аналіз допущених помилок.
